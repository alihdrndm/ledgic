# Support

Ledgic is an open-source portfolio project maintained by one person in their spare time. Support is
best-effort: there is no SLA, no commercial support and no guarantee that a question gets an answer.

## Where to go

| You want to... | Do this |
|---|---|
| Report a bug in the code or the live demo | Open a [bug report](https://github.com/alihdrndm/ledgic/issues/new?template=bug_report.yml) |
| Suggest a feature or improvement | Open a [feature request](https://github.com/alihdrndm/ledgic/issues/new?template=feature_request.yml) |
| Ask a usage or setup question | Open a [question](https://github.com/alihdrndm/ledgic/issues/new?template=question.yml) |
| Report a security vulnerability | **Privately**, as described in [SECURITY.md](SECURITY.md). Never in a public issue |
| Report a Code of Conduct concern | Email the address in [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md#enforcement) |
| Get a read-only MCP token for the hosted demo | Open a question; tokens are never posted publicly |

## Before asking

- Read the [README](README.md), especially [Run locally](README.md#run-locally), and the docs in
  [`docs/`](docs/): [ARCHITECTURE](docs/ARCHITECTURE.md), [AGENTS_RAG](docs/AGENTS_RAG.md),
  [MCP](docs/MCP.md) and [RUNBOOK](docs/RUNBOOK.md) (which has a "Common failures" section).
- Search [existing issues](https://github.com/alihdrndm/ledgic/issues?q=is%3Aissue), open and closed.

## When asking

- Include versions (Node, pnpm, Python, uv, Docker, OS), the exact command and the full error output.
- Remove API keys, tokens, passwords, `.env` contents and personal data before posting anything.

The hosted demo runs on free tiers and resets nightly. Short outages are expected and are not usually worth
an issue unless they last more than a day.
